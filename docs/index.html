MiniJava Static Analyzer

Ένας static analyzer για τη MiniJava, υλοποιημένος σε Java με JTB και JavaCC. Αποτελεί το front-end ενός MiniJava compiler: symbol table, type checking και memory layout computation.

Java JTB JavaCC Visitor Pattern

📖 Σχετικά με την Εργασία

Η παρούσα εργασία αποτελεί τη 2η Προγραμματιστική Εργασία του μαθήματος «Μεταγλωττιστές». Υλοποιεί έναν στατικό αναλυτή (static analyzer) για τη γλώσσα MiniJava, που εκτελεί τρεις βασικές αναλύσεις:

1️⃣ Symbol Table

Καταγραφή όλων των κλάσεων, πεδίων, μεθόδων, παραμέτρων και τοπικών μεταβλητών σε ένα hash map.

2️⃣ Type Checking

Έλεγχος ορθότητας τύπων σε expressions, statements, method calls και inheritance.

3️⃣ Offset Calculation

Υπολογισμός του memory layout κάθε κλάσης — offsets πεδίων και μεθόδων στη μνήμη.

⚠️ Σημείωση: Υλοποιείται μόνο το front-end του compiler. Το code generation (Vapor / SPIGLET / bytecode) δεν έχει υλοποιηθεί. Δείτε τη σελίδα Περιορισμοί.

🔀 Pipeline

Ο analyzer αποτελείται από τρία ανεξάρτητα passes, κάθε ένα από τα οποία διατρέχει το AST με visitor.

Shared state: Και τα τρία passes μοιράζονται το ίδιο SymbolTable και το ίδιο AST root (Goal). Κάθε pass διατρέχει το δέντρο ανεξάρτητα.

Pipeline Analysis

Πώς ρέουν τα δεδομένα μέσα από τα 3 passes

📊 Διάγραμμα Ροής

MiniJava source (.java) │ ▼ [JTB + JavaCC] → parse tree │ ▼ MyVisitor_ST → Symbol Table │ ▼ MyVisitor_TC → Type checking │ ▼ MyVisitor_OffSet → Field / Method offsets │ ▼ print (offsets)

🎯 Main.java — Ο Driver

  1. Έλεγχος argumentsΑν args.length < 1 → usage error.
  2. Άνοιγμα αρχείουFileInputStream για κάθε input file.
  3. ParseMiniJavaParser parser = new MiniJavaParser(fis) → Goal root = parser.Goal().
  4. Pass 1: Symbol TableSymbolTable st = new SymbolTable(); MyVisitor_ST eval = new MyVisitor_ST(st); root.accept(eval, null);
  5. Pass 2: Type CheckingMyVisitor_TC type_checking = new MyVisitor_TC(st); root.accept(type_checking, null);
  6. Pass 3: Offset CalculationMyVisitor_OffSet offset = new MyVisitor_OffSet(st); offset.calculate_print();
  7. Exception handlingParseException και FileNotFoundException → stderr.
for (String filename : args) {
    System.out.println("\nFilename: " + filename);
    FileInputStream fis = new FileInputStream(args[0]);
    MiniJavaParser parser = new MiniJavaParser(fis);
    
    Goal root = parser.Goal();
    System.out.println("Program parsed successfully.");
    
    // PASS 1: Symbol Table
    SymbolTable st = new SymbolTable();
    MyVisitor_ST eval = new MyVisitor_ST(st);
    root.accept(eval, null);
    
    // PASS 2: Type checking
    MyVisitor_TC tc = new MyVisitor_TC(st);
    root.accept(tc, null);
    
    // PASS 3: Offset calculation
    MyVisitor_OffSet offset = new MyVisitor_OffSet(st);
    offset.calculate_print();
}

Pass 1 — Symbol Table

MyVisitor_ST.java

1 Σκοπός

Ο MyVisitor_ST διατρέχει το AST και γεμίζει το SymbolTable με πληροφορίες για:

  • Classes — όνομα και προαιρετικά parent (extends)
  • Fields — όνομα και τύπο (int, boolean, int[], boolean[], object)
  • Methods — return type, parameters, local variables
  • main — αντιμετωπίζεται ως method με ένα String[] parameter

2 Δομές Δεδομένων

SymbolTable
st HashMap<String, ClassInfo> class name → ClassInfo
ClassInfo
node String class name
parent String parent class (extends)
fields LinkedHashMap<String, String> διατηρεί σειρά δήλωσης
methods LinkedHashMap<String, MethodInfo> διατηρεί σειρά δήλωσης
MethodInfo
returnType String π.χ. "int", "void", class name
parameters List<Parameter> λίστα (name, type)
localVars LinkedHashMap<String, String> τοπικές μεταβλητές
Parameter
name String όνομα παραμέτρου
type String τύπος παραμέτρου
LinkedHashMap: Χρήση LinkedHashMap (όχι HashMap) για fields και methods — η σειρά δήλωσης είναι κρίσιμη για τον υπολογισμό offsets στο Pass 3.

3 Visitor Methods

AST NodeΕνέργεια
GoalVisits MainClass + όλα τα TypeDeclarations
MainClassΔημιουργεί ClassInfo, προσθέτει τη main ως method
ClassDeclarationClassInfo με parent = null
ClassExtendsDeclarationClassInfo με parent = όνομα
VarDeclarationΠροσθέτει field ή local variable (ανάλογα με context)
MethodDeclarationΔημιουργεί MethodInfo, parse parameters, local vars
FormalParameterList/Tail/TermΣυλλογή παραμέτρων σε string
TypeΕπιστρέφει "int", "boolean", "int[]", "boolean[]"
IdentifierΕπιστρέφει το όνομα

Είναι commented out στο Main.java αλλά μπορεί να ενεργοποιηθεί για debugging.

Pass 2 — Type Checking

MyVisitor_TC.java

1 Σκοπός

Ο MyVisitor_TC είναι ένας GJDepthFirst<String, Void> visitor: κάθε visit method επιστρέφει ένα String που είναι ο τύπος:

  • Primitives: "int", "boolean"
  • Arrays: "int[]", "boolean[]"
  • Objects: το όνομα της κλάσης
  • null: "no type produced"

2 Έλεγχοι που εκτελούνται

NodeΈλεγχος
MainClassValidates body + main method
ClassDeclaration / ClassExtendsDeclarationParent class exists, no redeclaration
VarDeclarationDuplicate variable/parameter names
MethodDeclarationOverriding rules, no overloads, duplicate parameters, return type
AssignmentStatementType of RHS compatible with LHS
ArrayAssignmentStatementLeft side is array, index is int
IfStatement / WhileStatementCondition is boolean
PrintStatementArgument is int
ArrayLookupIndexed expr is array, index is int
NotExpressionOperand is boolean
Plus / Minus / TimesOperands are int
CompareExpressionOperands are int, result is boolean
AndExpressionOperands are boolean, result is boolean
ArrayLengthArgument is array
MessageSendMethod exists on receiver, arguments match
AllocationExpressionCannot instantiate main class
ThisExpressionOnly inside a class
Σφάλματα: Όλα τα type errors πετάγονται ως Exception με descriptive message. Το Main τα πιάνει και τα εκτυπώνει στο stderr.

3 Helper Functions

get_type(expr, ci, mi)

Αναλύει ένα variable name σε τύπο, ψάχνοντας με τη σειρά:

  1. ParametersΨάχνει στη λίστα παραμέτρων της τρέχουσας μεθόδου.
  2. Local variablesΨάχνει στις τοπικές μεταβλητές.
  3. Own fieldsΨάχνει στα πεδία της τρέχουσας κλάσης.
  4. Inherited fieldsRecursively ψάχνει στην parent class.

check_int_2 / check_boolean_1 / check_boolean_2

Ελέγχουν αν τα operands είναι σωστού τύπου (int ή boolean) για τις αντίστοιχες πράξεις.

in_methods(...)

Επιλύει method call σε συγκεκριμένη κλάση και επαληθεύει ότι τα ορίσματα ταιριάζουν με τις παραμέτρους.

4 Παραδείγματα Σφαλμάτων

Λάθος τύπος σε return

public int foo() {
    return true;  // expected int, got boolean
}
Exception: Wrong expression type in return!!

Λάθος τύπος σε condition

if (5) { ... }  // expected boolean, got int
Exception: Condition sould be boolean

Λάθος τύπος σε operator

int x = 3;
boolean b = x && true;  // x is int, not boolean
Exception: Operator '&&' requires boolean operand

Duplicate parameter

public int foo(int a, int a) { ... }
Exception: Duplicate parameter: a

Ειδικός κανόνας: Δεν επιτρέπεται η δημιουργία instance της κλάσης που περιέχει τη main:

Pass 3 — Offset Calculation

MyVisitor_OffSet.java

1 Σκοπός

Ο MyVisitor_OffSet υπολογίζει το memory layout κάθε user-defined κλάσης (η main class εξαιρείται). Για κάθε κλάση υπολογίζονται:

  • Field offsets — πού βρίσκεται κάθε πεδίο στη μνήμη
  • Method offsets — πού βρίσκεται κάθε μέθοδος στον vtable

2 Κανόνες Υπολογισμού

Fields

  1. Inherited fields firstΤα πεδία της parent class μπαίνουν πρώτα.
  2. Next offsetΤο επόμενο offset ξεκινά από parent.lastFieldOffset + size(parent.lastField).
  3. Type sizesint = 4, boolean = 1, arrays/objects = 8.

Methods

  1. Inherited methodsΤα methods της parent class αντιγράφονται με το ίδιο offset.
  2. New methodsΤα νέα (non-overriding) methods ξεκινούν από parent.lastMethodOffset + 8.
  3. Method sizeΚάθε method πιάνει 8 bytes.
Target machine: Οι κανόνες βασίζονται στο target machine του μαθήματος — int = 4, boolean = 1, references = 8, methods = 8.

3 Δομές Δεδομένων

ClassInfo_OffSet
name String class name
fields List<FieldInfo_Offset> ταξινομημένα πεδία
methods List<MethodInfo_Offset> ταξινομημένες μέθοδοι
FieldInfo_Offset / MethodInfo_Offset
name String όνομα
offset int −1 = not yet computed

4 Ροή Εκτέλεσης

  1. calculate_print()Για κάθε class στο SymbolTable: δημιουργία ClassInfo_OffSet και προσθήκη fields.
  2. Προσθήκη methodsΑν έχει parent: μόνο τα non-overriding. Αλλιώς: όλα.
  3. calculate(oi)Για κάθε ClassInfo_OffSet: υπολογισμός field offsets (με inheritance).
  4. Υπολογισμός method offsetsInherited methods διατηρούν το offset τους, νέα παίρνουν νέο.
  5. ΕκτύπωσηSkip κλάσεις που περιέχουν main, εκτύπωση των υπόλοιπων.

5 Παράδειγμα — Memory Layout

Input Classes

class A {
    int x;
    boolean y;
    
    public int foo() { ... }
}

class B extends A {
    int[] arr;
    
    public int bar() { ... }
}

Class A — Memory Layout

Offset Size Name Type
0 4 bytes A.x int
4 1 byte A.y boolean
0 8 bytes A.foo method

Class B — Memory Layout (με inheritance)

Offset Size Name Type
0 4 bytes B.x int (inherited)
4 1 byte B.y boolean (inherited)
5 8 bytes B.arr int[] (new)
0 8 bytes B.foo method (inherited)
8 8 bytes B.bar method (new)

Output

-------Class A------- -------Variables------- A.x : 0 A.y : 4 -------Methods------- A.foo : 0 -------Class B------- -------Variables------- B.x : 0 B.y : 4 B.arr : 5 -------Methods------- B.foo : 0 B.bar : 8

6 Σημαντικές Παρατηρήσεις

Inherited methods: Μια override μέθοδος διατηρεί το ίδιο offset με τη parent — έτσι λειτουργεί ο polymorphism μέσω vtable.
Method size = 8: Ανεξάρτητα από το πλήθος παραμέτρων — αντιπροσωπεύει έναν pointer στον κώδικα της μεθόδου.
Skip main class: Η κλάση που περιέχει τη main δεν εκτυπώνεται — δεν έχει νόημα να υπολογιστούν offsets για αυτήν.

📊 Συνολική Κάλυψη

Η παρούσα υλοποίηση αποτελεί μόνο το front-end ενός MiniJava compiler. Τα τρία πρώτα στάδια (symbol table, type checking, offset calculation) έχουν υλοποιηθεί πλήρως, αλλά το code generation λείπει εντελώς.

✓ Symbol Table
✓ Type Checking
✓ Offsets
✗ Code Generation

🐛 Αποκλίσεις από το Spec

1
No code generation (Vapor / SPIGLET / bytecode) Υλοποιείται μόνο το front-end του compiler: symbol table, type checking, και offset computation. Δεν παράγεται intermediate representation ή τελικός κώδικας.
2
Type checker δεν κάνει exhaustive subtype checks Κάποια expressions ελέγχονται μόνο για τις κοινές περιπτώσεις (int, boolean, arrays, γνωστές κλάσεις). Δεν γίνεται πλήρης έλεγχος subtype compatibility σε κάθε θέση.
3
Offset rules — hardcoded sizes Οι κανόνες offsets υποθέτουν συγκεκριμένα μεγέθη από τον target machine του μαθήματος: int=4, boolean=1, references=8, methods=8. Δεν είναι configurable.
4
printTable() commented out Η μέθοδος SymbolTable.printTable() υπάρχει αλλά είναι commented out στο Main.java. Μπορεί να ενεργοποιηθεί για debugging αλλά δεν εκτελείται by default.

✅ Τι Λειτουργεί Σωστά

✓ Symbol Table

Πλήρης καταγραφή classes, fields, methods, parameters, locals με LinkedHashMap για σειρά δήλωσης.

✓ Type Checking

17+ έλεγχοι τύπων — expressions, statements, method calls, inheritance, allocation.

✓ Offset Calculation

Σωστός υπολογισμός memory layout με inheritance — fields πρώτα, μετά methods.

✓ Visitor Pattern

Τρία ανεξάρτητα passes χρησιμοποιούν το ίδιο AST — καθαρός διαχωρισμός concerns.

🎯 Τι Θα Έπρεπε να Υπάρχει (Spec)

Σύμφωνα με την πλήρη εκφώνηση ενός MiniJava compiler, θα έλειπαν:

  1. Intermediate Representation (IR)Παραγωγή Vapor ή SPIGLET από το AST.
  2. Register AllocationΑνάθεση virtual → physical registers.
  3. Instruction SelectionΜετάφραση IR σε assembly.
  4. Code EmissionΠαραγωγή τελικού MiniJava bytecode ή assembly.
  5. Constant Propagation / FoldingΒελτιστοποιήσεις στο AST.

🔧 Προτεινόμενες Βελτιώσεις

  1. Ενεργοποίηση printTable()Προαιρετικό flag -debug για εκτύπωση του symbol table.
  2. Exhaustive subtype checksΈλεγχος subtype compatibility σε κάθε expression position.
  3. Configurable sizesCLI flags για τα μεγέθη των τύπων (int=4, boolean=1, κ.λπ.).
  4. IR generationΠροσθήκη 4ου pass για παραγωγή SPIGLET.
  5. Better error messagesLine numbers + column numbers στα exceptions.
  6. Warning systemNon-fatal warnings (unused variables, unreachable code).

📌 Συμπέρασμα

Ο analyzer υλοποιεί πλήρως τα τρία πρώτα στάδια ενός compiler front-end: symbol table construction, type checking, και memory layout computation. Χρησιμοποιεί καθαρή αρχιτεκτονική με τρεις ανεξάρτητους visitors που μοιράζονται το ίδιο AST.

Οι περιορισμοί είναι καταγεγραμμένοι ρητά στο README (section 9). Η βασική έλλειψη είναι το code generation — το οποίο αποτελεί το δεύτερο μισό ενός πλήρους compiler και απαιτεί σημαντικά περισσότερη δουλειά (IR design, register allocation, instruction selection).
