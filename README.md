# Compilers – HW2 (MiniJava Static Analyzer)

A MiniJava static analyzer built at NKUA. The project parses MiniJava source
files, builds a symbol table, performs type checking, and computes the memory
layout (offsets) of every class's fields and methods. It is the front-end
stage of a MiniJava compiler.

The project is built around **JTB** (Java Tree Builder) and **JavaCC**, and
uses the visitor pattern (`GJDepthFirst`) to walk the AST.

---

## 1. Overview

The pipeline of the program is:

```
MiniJava source (.java)
        │
        ▼  [JTB + JavaCC]  →  parse tree
        │
        ▼  MyVisitor_ST      →  Symbol Table (classes, fields, methods, locals)
        │
        ▼  MyVisitor_TC      →  Type checking
        │
        ▼  MyVisitor_OffSet  →  Field / Method offsets  (memory layout)
```

Each stage is a separate visitor that takes the same AST root (`Goal`) and the
shared `SymbolTable`.

## 3. Symbol Table (Pass 1 — `MyVisitor_ST`)

`MyVisitor_ST` walks the AST and fills the `SymbolTable` (a
`HashMap<String, ClassInfo>`) with the following information:

- **Classes** — name and optional parent class (`extends`).
- **Fields** — name and type (int, boolean, int[], boolean[], or object).
- **Methods** — return type, parameter list, and local variables.
- **`main`** — treated as a method of the main class with a single
  `String[]` parameter.

The three data classes are:

| Class | Holds |
|-------|-------|
| `ClassInfo` | `node`, `parent`, `fields` (LinkedHashMap), `methods` (LinkedHashMap) |
| `MethodInfo` | `returnType`, `List<Parameter> parameters`, `LinkedHashMap localVars` |
| `Parameter` | `name`, `type` |

**Notes:**

- `LinkedHashMap` is used for fields and methods to preserve declaration order —
  important for the offset stage.
- `SymbolTable.printTable()` can print the whole table (commented out in
  `Main.java` for debugging).

## 4. Type Checking (Pass 2 — `MyVisitor_TC`)

`MyVisitor_TC` is a `GJDepthFirst<String, Void>` visitor: every visit method
returns a `String` that is either a **primitive type** (`int`, `boolean`,
`int[]`, `boolean[]`) or a **class name**. `null` means "no type produced".

It checks, among other things:

| Node | Check |
|------|-------|
| `MainClass` | validates the body and the `main` method |
| `ClassDeclaration` / `ClassExtendsDeclaration` | parent class exists, no redeclaration |
| `VarDeclaration` | duplicate variable/parameter names |
| `MethodDeclaration` | overriding rules, no overloads, duplicate parameters, correct return type |
| `AssignmentStatement` | type of the RHS compatible with the LHS |
| `ArrayAssignmentStatement` | left side is an array, index is `int` |
| `IfStatement` / `WhileStatement` | condition is `boolean` |
| `PrintStatement` | argument is `int` |
| `ArrayLookup` | indexed expression is an array, index is `int` |
| `NotExpression` | operand is `boolean` |
| `Plus` / `Minus` / `Times` | operands are `int` |
| `CompareExpression` | operands are `int`, result is `boolean` |
| `AndExpression` | operands are `boolean`, result is `boolean` |
| `ArrayLength` | argument is an array |
| `MessageSend` | method exists on the receiver type and arguments match |
| `AllocationExpression` | cannot instantiate the class that contains `main` |
| `ThisExpression` | only inside a class |

Errors are thrown as `Exception` with a descriptive message. `Main` catches
them and prints the message to `stderr`.

**Helpers:**

- `get_type(expr, ClassInfo, MethodInfo)` — resolves a variable name to its
  type, searching in the order: parameters → local variables → own fields →
  inherited fields.
- `check_int_2`, `check_boolean_1`, `check_boolean_2` — operand-type checks.
- `in_methods(...)` — resolves a method call on a class and validates argument
  types.

## 5. Offset Calculation (Pass 3 — `MyVisitor_OffSet`)

Once the symbol table is built, `MyVisitor_OffSet` computes the **memory
layout** of every user-defined class (the class with `main` is skipped).

For each class:

1. **Fields**
   - Fields inherited from the parent are laid out first.
   - The next field offset starts from the parent's last field offset + its
     size.
   - Sizes: `int` = 4, `boolean` = 1, arrays/objects = 8.

2. **Methods**
   - Methods inherited from the parent are copied over with the same offset.
   - New (non-overriding) methods are appended starting from the parent's
     last method offset + 8.
   - Each method occupies 8 bytes.

The result is printed in the format:

```
-------Class <Name>-------
-------Variables-------
<ClassName>.<field> : <offset>
...
-------Methods-------
<ClassName>.<method> : <offset>
...
```

The helper classes:

| Class | Role |
|-------|------|
| `ClassInfo_OffSet` | Ordered list of `FieldInfo_Offset` and `MethodInfo_Offset` for a class |
| `FieldInfo_Offset` | `name`, `type`, `offset` |
| `MethodInfo_Offset` | `name`, `offset` (−1 means "not yet computed") |

## 6. Build & Run

### 6.1 Prerequisites

Two jars must be in the project root:

- `jtb132di.jar` — Java Tree Builder
- `javacc5.jar`  — JavaCC

### 6.2 Build

```bash
make all
# equivalent to:
# java -jar jtb132di.jar -te MiniJava.jj
# java -jar javacc5.jar MiniJava-jtb.jj
# javac syntaxtree/*.java visitor/*.java
# javac *.java
```

The first two commands generate `syntaxtree/`, `visitor/` and
`MiniJava-jtb.jj`, which are then compiled together with the hand-written
source files.

### 6.3 Run

1. Place your MiniJava input file(s) in `inputfiles/`.
2. Run:

```bash
make run
# equivalent to:
# java Main <inputfiles>
```

Or, to run a single file directly:

```bash
java Main path/to/File.java
```

### 6.4 Clean

```bash
make clean
```

Removes all `.class` files, the generated `syntaxtree/`, `visitor/`,
`MiniJava-jtb.jj`, and any `.java` file that was not hand-written (i.e. keeps
only `Main.java`, `MyVisitor_*.java`, `*Info*.java`, `Parameter.java`,
`SymbolTable.java`).

## 7. Program Output

For each input file the program prints:

```
Filename: <path>

Program parsed successfully.
-------Class A-------
-------Variables-------
A.x : 0
A.y : 4
-------Methods-------
A.foo : 0
...

-------Class B-------
...
```

If a type error is detected, an exception message is printed to `stderr`,
e.g.:

```
Wrong expression type in return!!
```

## 8. Design Notes

1. **Three independent visitors.** Each pass (`ST`, `TC`, `OffSet`) is a
   separate `GJDepthFirst` subclass. This keeps concerns isolated and makes
   debugging easier; the AST is traversed three times.

2. **`LinkedHashMap` for fields and methods.** Order matters for offset
   computation and for printing.

3. **Type as `String`.** The `GJDepthFirst<String, Void>` return type is used
   to propagate type names up the tree; primitives are `"int"`, `"boolean"`,
   `"int[]"`, `"boolean[]"` and objects are the class name itself.

4. **Exceptions for errors.** All semantic errors are reported by throwing an
   `Exception` with a message; the top-level `Main` catches and prints them.

5. **`-te` JTB flag.** `-te` produces a "tree" version of the AST without
   extra visitor-generation logic, which is enough for our needs.

## 9. Known Limitations

- Only the front-end of the compiler is implemented: symbol table, type
  checking, and offset computation. **No code generation (Vapor / SPIGLET /
  MiniJava bytecode) is performed.**
- The offset rules assume the same sizes used by the course's target machine
  (`int` = 4, `boolean` = 1, references = 8, methods = 8).
- The type checker does not perform exhaustive subtype checks in every
  position; some expressions are only validated for the common cases
  (`int`, `boolean`, arrays, and known classes).
- `SymbolTable.printTable()` is present but commented out in `Main.java`; it
  can be re-enabled for debugging.
